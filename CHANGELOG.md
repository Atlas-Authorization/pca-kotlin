# Changelog

## Unreleased (0.6.0)

- Breaking: `Optimistic.claimStatus` throws `IllegalArgumentException` for a clock or challenge window that is not a finite time, instead of returning `finalized`, which opens settlement.
- Fixed: a NaN, +Infinity or -Infinity clock, age, skew, spend, budget or amount now refuses everywhere a time, budget, amount or limit comparison is made, as the TypeScript reference does.

## Unreleased (0.5.0, action kit)

- Added: the opt-in native modules install with no manual native build. `pca-pairing`, `pca-mpc-lwe-ot`, `pca-fndsa` and `pca-fhe-seal` carry their libraries in the jar (`natives/<os>-<arch>/`), and the new `pca-natives` module carries the LESS library and the reference WebAssembly host with its SHA-256 pin (`PackagedNatives.wasmtimeHost()`). JVM only; environment and property overrides still win. `pca-fhe-seal` (Gradle build) now takes the Java core as a dependency, as `pca-fndsa` does.

- Fixed: a shared-payment-token period end, a present ACP spend cap, a stream-health clock or verification timeout, a replay-guard clock or expiry, an ID-token, JWT-SVID or transaction-token tolerance, the bond cap and balance checks, and a bond challenge status clock that is not finite now refuse instead of admitting or finalizing; an unknown AP2 recurrence frequency is always a violation.

- Fixed: a clock, age, spend, remaining budget, timeout or attempt count that is NaN, +Infinity or -Infinity now refuses (expires, depletes or gives up) instead of admitting, across the replay stores, standing approvals, sliding-window counter, Stripe signature check, challenge windows, budget debits, SD-JWT key binding, SET and web-bot-auth freshness, mesh heads and actions, attestation freshness, DLP, step-up retry limit and the AP2 / ACP bounds.

### Agent side

- Changed (agent side): matches the reference in three facade places. `Catalog.Spec` gains `resource` (optional, last): the compiled predicate uses it as given and only an absent one means any resource (`*`); an empty resource stays empty. A string or array `weights` in a `compilePolicy` risk-policy override adds its indices (`"0"`, `"1"`, ...) as the reference's object spread does; no weight reads those keys, so scoring is unchanged. The risk of a dollar action reads its amount as JavaScript's `Number()` does: a one-element array converts through its element (`[1]` is 1, `[]` and `[null]` are 0, `[true]` is NaN), `0x`/`0o`/`0b` strings are read in their radix, and `1f`, `1d` or hex floats are NaN (the blast radius) instead of a number.
- Changed (agent side): `Issue.signPCActn` keeps the body's other members as given, as the reference's `signPCActnSuite` does (`{...body, sig}` for Ed25519; `alg`, `pq_pk`, `sig` and a hybrid's `pq_sig` set from the signer otherwise). It no longer drops a `threshold`, `pq_sig`, `alg` or `pq_pk` the caller left in the body.
- **Security** (agent side): `Issue.mintGrant` now runs the reference's envelope checks before signing (risk policy, units, tighten rules, template link, action pins, provenance, model polarity), with the reference's messages, and keeps only the envelope members the reference keeps; before, it signed any envelope, so a grant every verifier refuses could be minted. A missing `risk_policy` is now reported by the risk-policy check.
- Added (agent side): `Agent.fromPrincipal` and `Facade` (compile permissions and limits into the grant; `act`, `dryRun`, `subAgent`, `budget`, `autonomyBound`, `encodeGrant`), `Facade.compilePolicy`, `Facade.parseLimit`, the built-in `Catalog`, `Issue.signPCActn`, `Issue.headers`, and `SignersMore` (every remaining producer of the shared producer vectors). LESS signing is refused with `unsupported_suite: <alg>`.

### Security (fixes for 0.4.x, see the [security advisory](https://github.com/Atlas-Authorization/pca/blob/main/docs/pca/advisories/2026-11-pca-0.4.x.md))

- **Budget allocations (fixed in 0.5.0; 0.4.3 and earlier affected).** A delegation chain whose child carried a larger `budget_alloc` than its parent passed chain verification; only a non-negative limit was checked. A widening chain now fails.
- **`zk_compliance` (fixed in 0.5.0; 0.4.3 and earlier affected).** A PCActn carrying `zk_compliance` passed the core verifier and the signature-only guards with no zero-knowledge verifier checking it. It now fails unless a verifier enforced it.

- Added (policy gates): `Authorize` options `resolvePrincipal` / `requireVerifiedPrincipal` (`principal` check), `requirePassport` / `passport` (`passport` check, before any replay state is written), `requireLinkedTemplate` (`template`), `forbid` / `forbidCertificate` (the allow carries the forbid-wins certificate as `result.forbid`) and `contracts` (peeked before the replay counter, committed after it). New `Prohibitions`, `Contracts`, `ContractEnforcer` and `ForbidWins`: the signed constitution, the safety-evidence verifier, the bounded temporal contracts and the order-independent forbid-wins decision, replayed over the shared vectors.
- Added: `StoreConformance.runBudgetStore` and `StoreConformance.runKvRegistries`; `Keys.EdKey.destroy()` / `Keys.PqKey.destroy()` zero the secret bytes.
- Added: the policy layer's `policy_decision` vectors are replayed in full, and the risk, taint, beacon and freshness-anchor gates have their own tests.

- **Security, breaking** (authorize): with `pqPins` set, a classical (Ed25519) grant whose issuer has a pin is refused (`pq_pin: the grant issuer is pinned to a post-quantum key; a classical grant is refused`); before, the pin protected nothing against a holder of the issuer's Ed25519 key. Unpinned issuers, empty pins and unset pins are unchanged.
- **Testing**: mutation testing now covers every shipped source file: the step-up client, the shared guard, and the Ktor and Spring modules joined the verifier, and the run fails if a shipped file has no mutants. `AndroidKeystoreSecretStore` is mutated against in-memory stand-ins for the Android classes, so those tests cover the store's own logic, not Android's Keystore or `EncryptedSharedPreferences`.
- **Security, breaking** (attestation): the Intel PCS collateral body now comes from the signed bytes. A later duplicate `tcbInfo` or `enclaveIdentity` member could replace the signed body, so a revoked or out-of-date platform could report UpToDate.
- **Security, breaking** (attestation): a GCP Confidential Space JWK that carries an `x5c` must be the key of its own leaf. Before, a genuine chain placed beside an attacker's key was accepted.
